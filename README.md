# WorkStintionJobSimulator
Симулятор роботи "коробки" (робочої станції), яка живе в умовах:

- повітряних тривог;
- відключень світла;
- можливих комбінованих сценаріїв (відключення світла + тривога).

Проєкт показує:

- як **генеруються події** з різною ймовірністю;
- як **відділити логіку сценаріїв** (події) від **фізики коробки** (живлення, тривога, батарея, тощо);
- як **зручно логувати** те, що відбувається.

## Структура репозиторію
- `WorkstationJobSimulator` — консольний застосунок із симуляцією робочої станції та фізикою подій.
- `TelemetryGenerator.Core` — бібліотека для генерації телеметрії з моделями вузла, аномаліями та сценаріями.
- `TelemetryGenerator.Cli` — CLI-утиліта, що обгортає `TelemetryGenerator.Core` і формує CSV.
- `TelemetryGenerator.DataQualityChecker` — бібліотека для перевірки згенерованих CSV (структура, час, фізика, аномалії).
- `AI.Training` — допоміжні матеріали для ML/AI-тренувань на телеметрії.

## Налаштування за замовчуванням
### Симулятор робочої станції
Параметри, що використовуються під час запуску `WorkstationJobSimulator`, визначені в `Models/SimulationParameters.cs`:
- Назва станції: `"Робоча станція №1"`.
- Кількість ітерацій: `5`.
- Інтервал між подіями: від `20` до `40` секунд.
- Затримка перед стартом: `2` секунди для перегляду конфігурації перед стартом.

### Генератор телеметрії (CLI)
CLI спирається на словник стандартних аргументів у `TelemetryGenerator.Cli/Program.cs`, який підхоплюється автоматично, якщо не вказати явні параметри:
- Сценарій: `normal-day`.
- Складність: `Normal`.
- Початок: поточний час у ISO-форматі (`DateTime.Now`).
- Тривалість моделювання: `24h`.
- Крок вибірки: `5` хвилин (`--step-minutes 5`).
- Ідентифікатор станції: `WS-001`.
- Кількість динаміків, підключених у вузлі: `4`.
- Профіль вузла: `randomized` (випадкова конфігурація параметрів вузла за замовчуванням).
- Шлях до вихідного CSV: `./telemetry.csv` у поточній директорії запуску.

## Порядок запуску
1. **Підготувати середовище**: встановити .NET 8 SDK (проєкти таргетують `net8.0`). Виконати відновлення залежностей та збірку:
   ```bash
   dotnet restore
   dotnet build
   ```

2. **Запустити симулятор робочої станції** (`WorkstationJobSimulator.csproj`):
   ```bash
   dotnet run --project WorkstationJobSimulator.csproj
   ```
   На старті виводяться параметри за замовчуванням; після натискання клавіші запускаються ітерації генерації подій та застосування фізики.

3. **Запустити генератор телеметрії** (`TelemetryGenerator.Cli`), вказавши або підтвердивши аргументи:
   ```bash
   dotnet run --project TelemetryGenerator.Cli/TelemetryGenerator.Cli.csproj -- \
     --scenario normal-day \
     --difficulty Normal \
     --start 2024-01-01T08:00:00 \
     --duration 24h \
     --step-minutes 5 \
     --workstation-id WS-001 \
     --speakers-configured 4 \
     --output ./out/telemetry.csv
   ```
   Якщо окремий параметр не вказаний, застосовується його значення з блоку "Налаштування за замовчуванням" вище. Файл `telemetry.csv` буде створено в обраній директорії.

4. **Перевірити якість даних** (опційно): бібліотека `TelemetryGenerator.DataQualityChecker` надає клас `DataQualityChecker` з методом `Run(csvPath, datasetName)`, який повертає markdown, JSON та структурований звіт про якість телеметрії. Використайте цей клас у власних інструментах/тестах для валідації CSV.

## Типові конфігурації
- **Змінити тривалість або крок симуляції CLI:** передайте інші значення в `--duration` (наприклад, `12h` або `2d`) і `--step-minutes`.
- **Запустити інший сценарій:** параметр `--scenario` підтримує `normal-day`, `powerloss`, `speakers-degradation`, `net-failure`, `cooling-service` та їхні синоніми.
- **Фіксована конфігурація вузла:** використайте `--node-profile fixed`, щоб застосувати базову конфігурацію замість рандомізованої.
